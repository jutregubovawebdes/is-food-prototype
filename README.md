# IS.Food — интерфейс заказа обедов

Автономный интерактивный прототип для передачи разработчику. HTML, CSS и JavaScript, без сборки, внешних библиотек и реальных запросов. Мобильный и десктопный интерфейсы — одна адаптивная страница.

## Запуск

Нужен Node.js 20 или новее. Устанавливать зависимости не требуется:

```sh
npm start
```

- Десктоп / адаптив: http://127.0.0.1:4173/
- Мобильная рамка 393 × 852: http://127.0.0.1:4173/preview.html
- Тесты: `npm test`

Альтернатива с Python: `python3 -m http.server 4173 --bind 127.0.0.1 --directory public`.
Открывайте через HTTP, не двойным кликом по HTML.

## Файлы

- `public/index.html` — приложение.
- `public/preview.html` — мобильное превью.
- `public/styles.css` — вся вёрстка и адаптивные стили.
- `public/app.js` — состояние, шаблоны экранов, расчёты и обработчики.
- `public/fixtures.js` — меню с демонстрационными данными.
- `public/config.js` — дата и часовой пояс для воспроизводимого тестирования.
- `server.mjs` — локальный сервер, только чтение разрешённых файлов.
- `docs/INTEGRATION.md` — точки подключения методов, правила и ограничения.
- `docs/QA.md` — проверка сценариев и перечень проверенных состояний.

## Важно для тестирования

По умолчанию часы зафиксированы на 20.10.2026, 12:00 в Екатеринбурге, чтобы коллеги могли проверить заказ, редактирование и отмену независимо от реального времени. Заказ оформляется на 21.10.2026. Для проверки дедлайна измените `fixedNow` в `public/config.js`; `null` включает реальные часы браузера.

Первый экран — профиль с существующим заказом. Перейдите в «Меню»: можно изменить или отменить заказ, затем выбрать несколько комплексов. Перезагрузка возвращает исходные данные.

Авторизация имитируется, данные хранятся только в оперативной памяти. Кнопка оплаты только изменяет локальное состояние. QR — декоративная матрица без платёжных реквизитов. Не вводите реальные персональные данные или реквизиты. Эти пояснения намеренно находятся в документации, а не внутри согласованного интерфейса.

## Публикация

Публикуется только каталог `public/`. Он поддерживает размещение в подпапке репозитория: все пути относительные.

Для GitHub Pages используйте источник «GitHub Actions» и приложенный workflow. Он запускает тесты и публикует только `public/`, а не документацию или служебные файлы. Публикация в публичном репозитории делает исходники и превью доступными всем.

Не подключайте производственные API к публичному демонстрационному экземпляру. Сейчас CSP блокирует все сетевые запросы (`connect-src 'none'`).
