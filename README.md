# IS.Food — интерфейс заказа обедов

Автономный интерактивный прототип для передачи разработчику. HTML, CSS и JavaScript, без сборки, внешних библиотек и реальных запросов. Мобильный и десктопный интерфейсы — одна адаптивная страница.

## Запуск

Нужен Node.js 20 или новее. Устанавливать зависимости не требуется:

```sh
npm start
```

- Десктоп / адаптив: http://127.0.0.1:4173/
- Мобильная рамка 393 × 852: http://127.0.0.1:4173/preview.html
- Тесты: `npm test`

Альтернатива с Python: `python3 -m http.server 4173 --bind 127.0.0.1 --directory public`.
Открывайте через HTTP, не двойным кликом по HTML.

## Файлы

- `public/index.html` — приложение.
- `public/preview.html` — мобильное превью.
- `public/styles.css` — вся вёрстка и адаптивные стили.
- `public/app.js` — состояние, шаблоны экранов, расчёты и обработчики.
- `public/fixtures.js` — меню с демонстрационными данными.
- `public/config.js` — дата и часовой пояс для воспроизводимого тестирования.
- `server.mjs` — локальный сервер, только чтение разрешённых файлов.
- `docs/INTEGRATION.md` — точки подключения методов, правила и ограничения.
- `docs/QA.md` — проверка сценариев и перечень проверенных состояний.

## Важно для тестирования

По умолчанию часы зафиксированы на 20.10.2026, 12:00 в Екатеринбурге, чтобы коллеги могли проверить заказ, редактирование и отмену независимо от реального времени. Заказ оформляется на 21.10.2026. Для проверки дедлайна измените `fixedNow` в `public/config.js`; `null` включает реальные часы браузера.

Первый экран — «Меню» с остатком 500 ₽, без текущих заказов. Количества всех комплексов равны нулю, можно выбрать один или несколько комплексов и оформить заказ. В профиле у Ивана 7 тестовых операций: начисления, сгорание, списания за обеды и оплата по СБП. У Анны 4 операции: начисления, сгорание и списание. Операции каждой карты дают остаток 500 ₽; СБП оплачивается отдельно. Эти записи не создают текущих заказов. Перезагрузка возвращает исходное состояние и открывает «Меню».

Авторизация имитируется, данные хранятся только в оперативной памяти. «Подтверждаю оплату» только изменяет локальное состояние и не проверяет поступление денег. QR содержит предоставленную заказчиком реальную ссылку СБП; сканирование в банковском приложении может привести к реальному переводу. Для тестирования перевод не выполняйте. Номер карты в подсказке берётся из выбранной карты. Об оплате пользователь сообщает в чате «ITIS обеды» в Telegram или MAX самостоятельно; интеграций с мессенджерами нет. Эти пояснения намеренно находятся в документации, а не внутри согласованного интерфейса.

### Один аккаунт сотрудника, несколько карт

Сессия принадлежит Ивану Иванову (`ivan.ivanov`). Вход и выход относятся только к сотруднику, не к владельцу выбранной карты. Логин и пароль имитируются; реальные корпоративные данные не вводить.

Изначально привязаны карты №1771 (Иван Иванов) и №2384 (Анна Петрова). В шапке показываются владелец и номер выбранной карты; меню позволяет переключить карту, добавить или открыть управление картами. В профиле отдельно показан аккаунт сотрудника и выбранная карта.

Добавление требует только номера. Тестовый справочник: 1771, 2384, 3096 (Алексей Смирнов). Для проверки добавления используйте **3096**. Имя и баланс 500 ₽ берутся из справочника; неизвестный номер и повторное добавление показывают ошибку. Пользовательских названий карт нет.

Основная карта сотрудника №1771 всегда показана в разделе аккаунта в профиле, независимо от выбранной карты. В управлении она отмечена «Карта вашего аккаунта», кнопки удаления нет; запрет действует и в логике. Удаление дополнительной карты с подтверждением не отменяет заказы и не обнуляет баланс. Повторное добавление восстанавливает её данные в пределах текущей страницы. Выход из аккаунта не удаляет карты.

Баланс, заказы, корзина и история разделены по картам. Всё пока хранится в оперативной памяти; перезагрузка возвращает две исходные карты. Реальную базу и авторизацию должен подключить разработчик.

Под QR есть ссылка «Открыть оплату» на тот же реальный адрес СБП. При тестировании ссылку не открывать и деньги не переводить.

## Публикация

Публикуется только каталог `public/`. Он поддерживает размещение в подпапке репозитория: все пути относительные.

Для GitHub Pages используйте источник «GitHub Actions» и приложенный workflow. Он запускает тесты и публикует только `public/`, а не документацию или служебные файлы. Публикация в публичном репозитории делает исходники и превью доступными всем.

Не подключайте производственные API к публичному демонстрационному экземпляру. Сейчас CSP блокирует все сетевые запросы (`connect-src 'none'`).
